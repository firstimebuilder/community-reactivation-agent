# Community Reactivation Agent

A Fo MCP hackathon project that helps community managers turn member activity into thoughtful, human-reviewed re-engagement actions.

## The problem

I manage a 160-member Skool community. Encouraging members to participate in coaching sessions and community discussions requires tracking, follow-up, and personalized outreach.

## Current workflow

Fo is scheduled to update our Google Sheet of member activity every night. This data-tracking step is already automated; member reactivation is not yet an end-to-end automated workflow.

## Proposed solution

Extend the existing scheduled tracking workflow with an assistant that:

1. Reads member activity from a Google Sheet or demo dataset.
2. Identifies disengaged members using clear engagement rules.
3. Recommends a relevant next step, such as joining a coaching session.
4. Drafts personalized outreach for the community manager to review.

Every outreach message requires human approval.

## Hackathon scope

The first version will focus on producing a useful reactivation queue: member activity, reason for selection, recommended action, and draft message.

Direct Skool integration, automated message sending, and scheduling the new reactivation workflow are outside the initial scope. The existing nightly data update remains in place.

## Fo MCP integration

The project aims to use Fo MCP to extend the existing scheduled Fo workflow. The exact integration will be confirmed after reviewing the available Fo tools and access instructions.

## Privacy and safety

- Public demos will use fictional or carefully sanitized data.
- No private member data, credentials, or spreadsheet access links will be committed to this repository.
- Recommendations will distinguish observed activity from assumptions.
- No messages will be sent automatically.

## Project status

Planning and teammate formation. The nightly Fo data-tracking workflow already exists; the reactivation application has not yet been built.
